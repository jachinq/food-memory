# 食忆 App 原型页面设计

## 1. 设计目标

食忆是一个同时适配 PC 端和手机端的响应式 Web 应用。原型设计目标是：

- 图片优先，帮助用户通过视觉回忆菜品。
- 操作轻量，手机端可以快速记录。
- 信息完整，PC 端适合整理菜品库和批量回顾。
- 同一套 Vue + Vite 前端通过响应式布局覆盖桌面与移动端。

## 2. 设计原则

1. 先看到菜，再看到信息：菜品卡片优先展示图片、菜名、状态。
2. 表单分段：新增菜品和制作记录采用分组折叠/分段表单，避免手机端过长压迫感。
3. 快速入口固定：手机端底部固定新增按钮，PC 端顶部工具栏新增按钮。
4. 回忆优先：首页不是普通仪表盘，而是“帮你想起旧菜”。
5. 响应式而非两套系统：PC 和手机共用页面组件，根据断点调整布局。

## 3. 响应式断点建议

| 断点 | 设备 | 布局策略 |
| --- | --- | --- |
| < 768px | 手机 | 单列卡片流、底部导航、抽屉筛选 |
| 768px - 1199px | 平板/小屏 | 双列卡片、顶部导航 |
| >= 1200px | PC | 多列卡片、侧边筛选、详情可宽屏展示 |

## 4. 全局导航

### 4.1 PC 端导航

顶部导航栏：

```text
[食忆 Logo]  [首页] [菜品库] [复做清单] [统计]                [搜索框] [+ 新增菜品]
```

特点：

- 顶部固定或半固定。
- 搜索框常驻。
- 新增按钮明显。

### 4.2 手机端导航

底部 Tab：

```text
首页    菜品库    +    复做    我的
```

中间“+”为主要动作按钮，点击后弹出：

- 新增菜品
- 记录制作
- 上传截图


首页模块：

- 想做清单：状态为 want_to_cook。

## 5.3 新增/编辑菜品页面

表单分组：

1. 基础信息：菜名、状态、封面图。
2. 来源信息：来源链接、来源平台、截图。
3. 分类信息：食材、标签、口味、场景。
4. 制作信息：难度、耗时、评分。
5. 备注信息：想做原因、注意事项。

手机端采用单列分组；PC 端可左右两栏：左侧图片与来源，右侧表单字段。

## 5.5 记录制作页面

字段：

- 制作日期
- 上传成品照片
- 本次结果：成功/一般/失败
- 本次评分
- 本次改动
- 翻车原因
- 下次注意
- 备注

交互：

- 如果结果选择“失败”，显示翻车原因输入框。
- 如果评分 >= 4，提示是否标记菜品为“做成功/想再做”。
- 保存后返回菜品详情。

## 5.6 复做清单页面

展示用户近期想再做的菜。

模块：

- 计划中
- 本周建议
- 已完成

操作：

- 标记已完成，并引导记录一次制作。
- 取消复做计划。
- 修改计划日期。

## 7. 视觉风格建议

- 主色：温暖橙色或番茄红，强调食物记忆和厨房温度。
- 辅色：米白、浅灰、深棕。
- 卡片圆角：12px - 16px。
- 图片比例：列表 4:3 或 1:1，详情 16:9 或自适应。
- 字体：系统默认中文字体，保证跨平台稳定。

## 8. 关键空状态文案

- 菜品库为空：还没有记录菜，先把最近想做的一道菜存进来吧。
- 搜索无结果：没找到相关菜品，试试搜索食材、口味或标签。
- 制作记录为空：这道菜还没有制作记录，做完后记得回来补一条。
- 推荐为空：高评分旧菜还不多，继续记录几次后我就能帮你回忆啦。
