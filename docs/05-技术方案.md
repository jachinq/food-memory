# 食忆技术方案

## 1. 技术栈硬性约束

- 后端：Golang
- 前端：Vue + Vite
- 交付产物：Docker 部署的 Web 应用
- 展示适配：同时做好 PC 端和手机端响应式展示

## 2. 总体架构

```text
Browser(PC/Mobile)
      │
      ▼
Vue + Vite SPA
      │ REST API / JSON
      ▼
Golang API Server
      │
      ├── PostgreSQL：结构化数据
      └── Local Storage / Object Storage：图片文件
```

MVP 推荐采用前后端分离开发、部署时前端静态文件由 Nginx 或 Golang 服务托管。为了简化 Docker 部署，可以使用 docker-compose 同时启动 app、postgres 两个服务。

## 3. 后端方案

### 3.1 推荐框架

- Web 框架：Gin 或 Echo，推荐 Gin，生态成熟，上手快。
- ORM：GORM，便于快速实现 CRUD 和迁移。
- 配置：Viper 或环境变量直接读取。
- 日志：zap 或 slog；MVP 可用 Go 标准库 slog。
- 数据库：PostgreSQL。
- 图片处理：MVP 先保存原图，后续使用 imaging 生成缩略图。

### 3.2 后端分层

```text
backend/
  cmd/server/main.go
  internal/config
  internal/router
  internal/handler
  internal/service
  internal/repository
  internal/model
  internal/middleware
  internal/storage
  migrations
```

分层职责：

| 层 | 职责 |
| --- | --- |
| handler | HTTP 参数解析、响应封装 |
| service | 业务逻辑，如新增制作记录后更新菜品统计 |
| repository | 数据库读写 |
| model | 数据模型与 DTO |
| storage | 图片上传、文件路径、缩略图处理 |
| middleware | 日志、跨域、错误处理 |

### 3.3 核心 API

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| /api/health | GET | 健康检查 |
| /api/dishes | GET | 菜品列表，支持搜索筛选分页 |
| /api/dishes | POST | 新增菜品 |
| /api/dishes/:id | GET | 菜品详情 |
| /api/dishes/:id | PUT | 编辑菜品 |
| /api/dishes/:id | DELETE | 删除菜品 |
| /api/dishes/:id/records | GET | 制作记录列表 |
| /api/dishes/:id/records | POST | 新增制作记录 |
| /api/records/:id | PUT | 修改制作记录 |
| /api/records/:id | DELETE | 删除制作记录 |
| /api/tags | GET | 标签列表 |
| /api/tags | POST | 新增标签 |
| /api/upload | POST | 图片上传 |
| /api/home/summary | GET | 首页汇总数据 |

### 3.4 响应格式

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

分页格式：

```json
{
  "items": [],
  "page": 1,
  "pageSize": 20,
  "total": 100
}
```

### 3.5 图片上传

MVP 方案：

- 上传目录：/app/uploads
- 访问路径：/uploads/{date}/{filename}
- 文件名：uuid + 扩展名
- 限制：单张 10MB 内，类型 jpg/jpeg/png/webp
- Docker 使用 volume 持久化 /app/uploads

后续扩展：

- 生成缩略图
- 接入 S3/MinIO/OSS
- 图片压缩

## 4. 前端方案

### 4.1 技术选型

- Vue 3
- Vite
- TypeScript
- Vue Router
- Pinia
- Axios 或 Fetch 封装
- UI 组件库：Element Plus 或 Naive UI；若更重视移动端，可自定义轻量组件 + CSS Grid/Flex。
- 样式：SCSS 或 CSS Variables。

### 4.2 目录结构

```text
frontend/
  src/
    api/
    assets/
    components/
    layouts/
    router/
    stores/
    styles/
    types/
    views/
      Home.vue
      DishList.vue
      DishDetail.vue
      DishForm.vue
      CookRecordForm.vue
      RecookPlan.vue
```

### 4.3 响应式实现

- 使用 CSS Grid 和 Flex 完成基础布局。
- 通过媒体查询控制 PC/手机布局。
- 断点：768px、1200px。
- PC 端使用顶部导航 + 侧边筛选。
- 手机端使用底部 Tab + 抽屉筛选 + 浮动新增按钮。

示例：

```css
.dish-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(220px, 1fr));
  gap: 16px;
}

@media (max-width: 767px) {
  .dish-grid {
    grid-template-columns: 1fr;
    gap: 12px;
  }
}
```

## 5. 数据库方案

推荐 PostgreSQL。

原因：

- Docker 部署成熟。
- JSONB 支持后续扩展。
- 模糊查询和索引能力较好。
- 后续多用户扩展容易。

MVP 表：dishes、cook_records、tags、dish_tags、attachments、recook_plans、app_settings。

## 6. Docker 部署方案

### 6.1 docker-compose 服务

```yaml
services:
  app:
    build: .
    ports:
      - "8080:8080"
    environment:
      APP_PORT: 8080
      DB_HOST: db
      DB_PORT: 5432
      DB_USER: shiyi
      DB_PASSWORD: shiyi_password
      DB_NAME: shiyi
      UPLOAD_DIR: /app/uploads
    volumes:
      - ./uploads:/app/uploads
    depends_on:
      - db

  db:
    image: postgres:16
    environment:
      POSTGRES_USER: shiyi
      POSTGRES_PASSWORD: shiyi_password
      POSTGRES_DB: shiyi
    volumes:
      - ./pgdata:/var/lib/postgresql/data
```

### 6.2 镜像构建

推荐多阶段构建：

1. node 阶段构建 Vue + Vite 前端。
2. golang 阶段编译后端二进制。
3. runtime 阶段复制二进制、静态文件和迁移文件。

## 7. 鉴权策略

MVP 如果是个人本地部署，可以先不做账号体系，但建议预留：

- 单用户访问口令
- 后续 JWT 登录
- user_id 字段扩展

如果部署在公网，至少需要增加登录或访问密码。

- 图片上传校验 MIME 和扩展名。
- 限制上传大小。
- API 参数校验。
- 防止路径穿越。
- 若部署公网，必须增加认证。
- 数据库密码通过环境变量注入。
