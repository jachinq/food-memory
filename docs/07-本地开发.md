# 本地开发

本机跑 Go API 和 Vue 前端，PostgreSQL 用 Docker 单独启动。完整应用镜像请看仓库根目录 `README.md` 的「Docker 部署」。

## 1. 环境要求

- Go 1.23+
- Node.js 20+、pnpm 10
- Docker（只用来跑开发库；也可以用局域网 Linux 上的 Docker）

## 2. 启动开发数据库

使用 `deployments/docker-compose.dev.yml`，它会把 Postgres **映射到宿主机端口**，本机 `go run` 才能连上。不要用生产用的 `docker-compose.yml` 只起 `db`：那个服务没有对外端口。

默认账号与 `backend/.env.example` 一致：用户/库名 `shiyi`，密码 `shiyi_password`。

### 2.1 本机 Docker

在仓库根目录：

```bash
docker compose -f deployments/docker-compose.dev.yml up -d
```

默认绑定 `0.0.0.0:5432`（本机和局域网都能连）。查看状态：

```bash
docker compose -f deployments/docker-compose.dev.yml ps
```

停止（数据保留在 Docker volume `shiyi_pgdata_dev`）：

```bash
docker compose -f deployments/docker-compose.dev.yml stop
```

清空开发库数据：

```bash
docker compose -f deployments/docker-compose.dev.yml down -v
```

宿主机 5432 已被占用时，换端口启动，并在 `backend/.env` 里把 `DB_PORT` 改成相同值：

```bash
DB_PORT=5433 docker compose -f deployments/docker-compose.dev.yml up -d
```

### 2.2 局域网 Linux 服务器上的 Docker

适合本机是 Windows、Linux 机器专门跑容器的情况。只把数据库放到服务器，前后端仍在本机开发（热重载、断点都在本机）。

1. 把仓库拷到 Linux，或至少拷贝 `deployments/docker-compose.dev.yml`。
2. 数据目录使用 Docker named volume，不要把 Windows 共享盘挂给 Postgres。
3. 启动开发库（默认已监听 `0.0.0.0:5432`）。若之前用旧配置只绑了 `127.0.0.1`，必须重建：

```bash
docker compose -f deployments/docker-compose.dev.yml up -d --force-recreate
```

防火墙只放行内网，例如：

```bash
sudo ufw allow from 192.168.2.0/24 to any port 5432
```

4. 本机探测端口：

```powershell
Test-NetConnection 192.168.2.131 -Port 5432
```

5. 把 `backend/.env` 的 `DB_HOST` 改成服务器局域网 IP，不要用 `db`（那是 Compose 内部主机名，只有同网络里的容器能解析）。

不要把 5432 映射到公网。开发默认密码是明文，局域网也建议改掉 `DB_PASSWORD`，Compose 与 `.env` 保持一致：

```bash
DB_PASSWORD=your-dev-password docker compose -f deployments/docker-compose.dev.yml up -d --force-recreate
```

## 3. 配置后端

在 `backend` 目录：

```bash
cp .env.example .env
```

Windows PowerShell：

```powershell
Copy-Item .env.example .env
```

按数据库位置修改 `.env`：

| 场景 | `DB_HOST` | `DB_PORT` |
| --- | --- | --- |
| 本机 Docker 开发库 | `127.0.0.1` | `5432`（或你改过的映射端口） |
| 局域网 Linux 开发库 | 服务器内网 IP，如 `192.168.1.50` | 与服务器映射端口一致 |

其余常用项：

- `UPLOAD_DIR=../uploads`：从 `backend` 目录启动时指向仓库根下的 `uploads/`
- `MIGRATION_DIR=./migrations`：首次连接会执行 SQL 迁移并 AutoMigrate，一般不必手工建表
- `APP_ACCESS_TOKEN`：开发可留空；有值时前端会走解锁页

进程环境变量优先于 `.env`。在 `backend` 或仓库根目录执行 `go run` 都能读到 `backend/.env`。

## 4. 启动后端

```bash
cd backend
go run ./cmd/server
```

默认监听 `http://127.0.0.1:8080`。日志出现「食忆 API 已启动」且没有 `database` 错误即表示已连上库。

## 5. 启动前端

```bash
cd frontend
pnpm install
pnpm dev
```

浏览器打开 [http://localhost:5173](http://localhost:5173)。Vite 会把 `/api` 和 `/uploads` 代理到 `http://127.0.0.1:8080`。

日常开发请用 5173，不要用生产 Compose 里的 8080（那是构建后的静态资源，改前端代码不会热更新）。

## 6. 推荐日常流程

1. 启动开发库（本机或局域网 Linux，只需一次，之后 `restart: unless-stopped` 会自动起来）。
2. `cd backend && go run ./cmd/server`
3. `cd frontend && pnpm dev`
4. 浏览器使用 `http://localhost:5173`

改表结构时编辑 `backend/migrations/` 后重启后端即可。

## 7. 常见问题

**`connection refused` / `dial tcp 127.0.0.1:5432`**

- 确认用的是 `docker-compose.dev.yml`，并且 `ps` 里 `db` 已 healthy。
- 本机 Docker Desktop 未启动，或端口被其它 Postgres 占用。
- 连局域网库时 `DB_HOST` 仍是 `127.0.0.1`。

**Linux 上容器在跑，Windows 连不上**

- 容器在跑，但端口只绑在 Linux 的 `127.0.0.1`（旧版 compose 默认如此）。在服务器上执行 `ss -lntp | grep 5432`，若只看到 `127.0.0.1:5432` 就会被拒绝。用最新 `docker-compose.dev.yml` 执行 `up -d --force-recreate`。
- 用了生产 `docker-compose.yml` 的 `db`（没有 `ports`），宿主机 5432 根本没开。
- 防火墙未放行 5432，或 IP/端口填错。

**不要和生产 Compose 抢同一套数据盘**

开发库使用独立 volume `shiyi_pgdata_dev`；生产 `docker-compose.yml` 使用仓库下的 `pgdata/` 目录，两者互不影响。不要在同一台机器、同一端口上同时起两套库。
