# 食忆小程序与网页端实现方案

## 1. 方案前提

用户硬性规定最终产物是部署到 Docker 上运行的 Web 应用，技术栈为：

- 后端：Golang
- 前端：Vue + Vite
- 部署：Docker
- 展示：同时适配 PC 端和手机端

因此本项目的主实现方案应优先选择“响应式 Web 应用”。小程序方案作为后续扩展或替代客户端方案评估，不作为 MVP 主交付。

## 2. 推荐结论

MVP 推荐：

> Golang API + Vue 3 + Vite 响应式 Web + Docker Compose 部署。

原因：

1. 一套前端同时覆盖 PC 和手机浏览器。
2. 满足 Docker Web 应用部署要求。
3. 开发成本低于同时开发小程序和 PC Web。
4. 后续可通过 PWA 增强移动端体验。
5. 如果未来要做小程序，Golang API 可以复用。

## 3. Web 端实现方案

### 3.1 架构

```text
PC Browser / Mobile Browser
          │
          ▼
Vue + Vite SPA
          │
          ▼
Golang REST API
          │
          ├── PostgreSQL
          └── Uploads Volume
```

### 3.2 前端功能

- 首页：最近做过、推荐复做、想做清单、随机旧菜。
- 菜品库：搜索、筛选、卡片流。
- 菜品详情：菜品基础信息、来源、制作历史。
- 新增/编辑菜品：响应式表单。
- 记录制作：上传成品图、评分、备注、下次注意。
- 复做清单：近期想再做的菜。

### 3.3 PC 端适配

PC 端重点是整理效率和信息密度。

实现策略：

- 顶部导航栏。
- 菜品库使用多列网格。
- 搜索框常驻顶部。
- 筛选条件使用左侧栏。
- 菜品详情采用左右分栏。
- 表单可使用双列布局。

### 3.4 手机端适配

手机端重点是快速记录和图片浏览。

实现策略：

- 底部 Tab 导航。
- 中间浮动新增按钮。
- 菜品库使用单列卡片流。
- 筛选使用底部抽屉。
- 图片上传支持相册/拍照。
- 表单单列展示，并按分组折叠。
- 详情页封面图置顶，操作按钮吸底或紧跟标题。

### 3.5 PWA 可选增强

后续可添加 PWA：

- 添加到手机桌面。
- 缓存前端静态资源。
- 离线查看已缓存菜品。
- 后续支持提醒通知。

PWA 不改变 Docker Web 应用本质，适合作为移动端体验增强。

## 4. 小程序实现方案评估

### 4.1 小程序优势

- 手机端入口更稳定。
- 上传照片体验好。
- 可使用微信生态能力。
- 用户不需要记住网址。

### 4.2 小程序劣势

- 不能覆盖 PC 端完整整理场景。
- 需要额外开发小程序客户端。
- 需要小程序审核和平台限制适配。
- 与“最终 Docker 部署 Web 应用”的硬性要求不完全一致。

### 4.3 如果未来要做小程序

建议后续新增独立小程序客户端，继续复用 Golang API。

架构：

```text
微信小程序
    │
    ▼
Golang REST API
    │
    ├── PostgreSQL
    └── Uploads / Object Storage

Vue + Vite Web
    │
    ▼
同一套 Golang REST API
```

注意事项：

- API 需要 HTTPS。
- 图片访问域名需要配置到小程序后台。
- 登录可使用微信登录，但后端需新增 user 表。
- 小程序端更适合“新增、查看、记录制作”，PC Web 更适合“整理、筛选、批量维护”。

## 5. Docker 部署实现

### 5.1 推荐目录

```text
shiyi/
  backend/
  frontend/
  deployments/
    Dockerfile
    docker-compose.yml
    docker-compose.dev.yml
  uploads/
  docs/
```

### 5.2 多阶段 Dockerfile 思路

```dockerfile
# frontend build
FROM node:20-alpine AS frontend-builder
WORKDIR /frontend
COPY frontend/package*.json ./
RUN npm install
COPY frontend/ ./
RUN npm run build

# backend build
FROM golang:1.22-alpine AS backend-builder
WORKDIR /backend
COPY backend/go.mod backend/go.sum ./
RUN go mod download
COPY backend/ ./
RUN go build -o shiyi ./cmd/server

# runtime
FROM alpine:3.20
WORKDIR /app
COPY --from=backend-builder /backend/shiyi /app/shiyi
COPY --from=frontend-builder /frontend/dist /app/public
COPY backend/migrations /app/migrations
ENV APP_PORT=8080
EXPOSE 8080
CMD ["/app/shiyi"]
```

Golang 服务需要：

- 提供 /api/* 接口。
- 提供 /uploads/* 图片静态访问。
- 提供 / 前端静态文件访问。
- SPA 路由 fallback 到 index.html。

### 5.3 docker-compose

```yaml
services:
  app:
    build:
      context: ..
      dockerfile: deployments/Dockerfile
    ports:
      - "8080:8080"
    environment:
      APP_PORT: 8080
      DB_HOST: db
      DB_PORT: 5432
      DB_USER: shiyi
      DB_PASSWORD: shiyi_password
      DB_NAME: shiyi
      UPLOAD_DIR: /app/uploads
    volumes:
      - ../uploads:/app/uploads
    depends_on:
      - db

  db:
    image: postgres:16
    environment:
      POSTGRES_USER: shiyi
      POSTGRES_PASSWORD: shiyi_password
      POSTGRES_DB: shiyi
    volumes:
      - ../pgdata:/var/lib/postgresql/data
```

## 6. 开发阶段建议

### 6.1 本地开发

开发库、本机与局域网 Linux Docker、`.env` 配置的完整步骤见 [07-本地开发.md](./07-本地开发.md)。摘要：

```bash
docker compose -f deployments/docker-compose.dev.yml up -d
cd backend && cp .env.example .env && go run ./cmd/server
cd frontend && pnpm install && pnpm dev
```

前端 Vite 开发服务器通过代理访问后端：

```ts
server: {
  proxy: {
    '/api': 'http://127.0.0.1:8080',
    '/uploads': 'http://127.0.0.1:8080'
  }
}
```

### 6.2 联调策略

- API 先定义 DTO 和 Mock 响应。
- 前端页面先用 Mock 数据完成原型。
- 后端完成接口后替换为真实 API。
- 图片上传单独优先联调。

## 7. 路线建议

### 阶段 1：响应式 Web MVP

完成 Docker Web 应用，覆盖 PC 和手机浏览器。

### 阶段 2：PWA 增强

让手机端接近 App 使用体验。

### 阶段 3：小程序客户端

如用户强依赖微信生态，再开发小程序端，复用 Golang API。

## 8. 最终建议

当前需求最适合先做 Web 端，不建议 MVP 同时做小程序。原因是用户明确要求 Docker 部署的 Web 应用，并且需要 PC 和手机端展示。响应式 Vue + Vite Web 可以最快形成完整闭环，小程序可作为后续增强入口。
