# 食忆 Web 应用 PRD 产品需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 食忆 |
| 产品类型 | 私人菜品记忆 Web 应用 |
| 目标平台 | PC Web、手机 Web |
| 后端技术栈 | Golang |
| 前端技术栈 | Vue + Vite |
| 部署方式 | Docker 部署 |
| 文档版本 | v1.0 |

## 2. 产品背景

用户在刷社交媒体时经常看到想复刻的美食内容，可能来自小红书、抖音、B 站、微博、公众号等平台。用户复刻成功后，如果没有系统记录，过一段时间容易忘记曾经做过哪些菜，甚至连菜名都想不起来。

传统菜谱应用偏“查找菜谱”，社交媒体收藏夹偏“收藏内容”，但它们都不能很好解决：我曾经做成功过哪些菜、哪些菜值得再次复做、上次制作有什么经验、忘记菜名时如何通过照片/食材/口味找回。

## 3. 产品定位

食忆是一个帮助用户记录、回忆、复做曾经做过的菜的私人菜品记忆应用。

一句话描述：

> 帮你记住那些曾经做成功、但后来被遗忘的好吃菜。

核心不是做大众菜谱平台，而是构建用户自己的“做菜记忆库”。

## 4. 目标用户与场景

### 4.1 目标用户

- 经常刷社交媒体并收藏美食内容的人
- 喜欢复刻菜谱但缺少系统记录的人
- 经常做饭、但容易忘记以前做过什么的人
- 想建立私人菜谱库的人

### 4.2 典型场景

1. 刷到一道菜，先保存为“想做”。
2. 复刻一道菜后，记录成品照片和心得。
3. 过一段时间不知道吃什么，从历史成功菜品中挑选。
4. 忘记菜名，但记得“鸡肉、甜辣、下饭”，通过标签找回。
5. 周末想安排菜单，查看“很久没做但评分高”的菜。

## 5. 产品目标

### 5.1 用户目标

- 快速记录想做和做过的菜
- 用照片、标签、食材、口味唤起记忆
- 沉淀每次复刻经验
- 主动发现值得复做的旧菜
- 降低“不知道吃什么”的决策成本

### 5.2 MVP 验证目标

- 用户是否愿意持续记录菜品
- 用户是否会使用复做提醒和历史推荐
- 图片 + 标签是否能有效帮助回忆
- PC 与移动端是否都能顺畅使用

## 6. 核心功能范围

### 6.1 菜品管理

用户可以新增、编辑、删除菜品。字段包括：菜名、封面图、来源链接、来源平台、状态、主要食材、标签、口味、场景、难度、耗时、评分、备注。

### 6.2 制作记录

用户每次制作一道菜时，可以添加一次制作记录。字段包括：制作日期、成品照片、本次评分、成功状态、本次改动、翻车原因、下次注意事项、备注。

### 6.3 菜品状态

| 状态 | 含义 |
| --- | --- |
| 想做 | 已收藏但未制作 |
| 已做 | 已尝试制作 |
| 做成功 | 复刻成功，值得保留 |
| 翻车 | 复刻失败或效果不佳 |
| 想再做 | 用户明确希望近期复做 |
| 暂不做 | 当前不计划制作 |

### 6.4 搜索与筛选

支持按菜名、食材、标签、口味、状态、难度、耗时、评分、最近制作时间查找。重点支持“忘记菜名”的非精确搜索，如“鸡肉”“甜辣”“快手”“下饭”“空气炸锅”。

### 6.5 首页回忆推荐

首页展示最近做过、很久没做但评分高、随机旧菜、想再做清单、本周推荐复做。

### 6.6 响应式展示

应用必须同时适配 PC 和手机端。PC 端信息密度高，适合整理和回顾；手机端图片优先，适合快速新增和单手浏览。

## 7. 用户流程

### 7.1 保存想做的菜

1. 用户点击新增菜品。
2. 填写菜名或临时标题。
3. 粘贴来源链接。
4. 上传截图或封面图。
5. 添加食材、口味、标签。
6. 状态设为“想做”。
7. 保存。

### 7.2 记录一次复刻

1. 用户进入菜品详情。
2. 点击“记录一次制作”。
3. 上传成品照片。
4. 填写日期、评分、成功状态。
5. 填写备注和下次注意。
6. 保存后系统更新菜品的最近制作时间、制作次数、综合评分。

### 7.3 查找被遗忘的菜

1. 用户进入菜品库。
2. 输入记得的关键词，如“豆腐”“酸辣”“汤”。
3. 系统返回匹配的菜品卡片。
4. 用户通过照片识别目标菜品。
5. 进入详情查看历史制作经验。

## 8. 页面列表

| 页面 | 说明 |
| --- | --- |
| 首页 | 最近做过、复做推荐、随机旧菜 |
| 菜品库 | 全部菜品列表、搜索、筛选 |
| 新增/编辑菜品 | 创建和维护菜品基础信息 |
| 菜品详情 | 菜品信息、来源、制作历史 |
| 记录制作 | 新增一次制作记录 |
| 复做清单 | 管理近期想再做的菜 |
| 设置 | 标签管理、数据导入导出等 |

## 9. 非功能需求

- 首屏加载尽量控制在 2 秒内。
- 菜品列表支持分页或无限滚动。
- 图片上传后生成缩略图，避免列表加载原图。
- 兼容最新版 Chrome、Edge、Safari、Firefox、iOS Safari、Android Chrome。
- 手机端新增记录流程尽量不超过 1 分钟。
- 最终以 Docker 镜像方式部署，支持环境变量配置数据库、上传目录、端口等。

## 10. MVP 验收标准

1. 可以新增、编辑、删除菜品。
2. 可以上传封面图和制作照片。
3. 可以记录多次制作记录。
4. 可以按关键词、标签、状态筛选菜品。
5. 首页可以展示最近做过、很久没做、随机推荐。
6. PC 与手机端都有良好响应式体验。
7. 可以通过 Docker 启动完整 Web 应用。

## 11. 后续扩展方向

- AI 识别截图中的菜名、食材和标签
- 从社交媒体链接自动提取信息
- 根据冰箱食材推荐历史菜品
- 定时复做提醒
- PWA 离线使用
- 多用户与家庭共享菜谱库
- 数据导入导出
- 菜品时间胶囊
