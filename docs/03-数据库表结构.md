# 食忆数据库表结构设计

## 1. 设计目标

数据库用于支撑私人菜品记忆 Web 应用，核心对象包括菜品、制作记录、标签、图片附件、复做计划。MVP 阶段推荐 PostgreSQL；个人轻量部署也可使用 SQLite，但 Docker 生产化建议 PostgreSQL。

本文 SQL 以 PostgreSQL 为参考。

## 2. 表结构总览

| 表名 | 说明 |
| --- | --- |
| dishes | 菜品表 |
| cook_records | 制作记录表 |
| tags | 标签表 |
| dish_tags | 菜品标签关联表 |
| attachments | 图片附件表 |
| recook_plans | 复做计划表 |
| app_settings | 应用设置表 |

## 3. 枚举约定

### 3.1 菜品状态

| 值 | 说明 |
| --- | --- |
| want_to_cook | 想做 |
| cooked | 已做 |
| success | 做成功 |
| failed | 翻车 |
| want_to_recook | 想再做 |
| paused | 暂不做 |

### 3.2 制作结果

| 值 | 说明 |
| --- | --- |
| success | 成功 |
| normal | 一般 |
| failed | 失败 |

### 3.3 标签类型

| 值 | 说明 |
| --- | --- |
| ingredient | 食材 |
| taste | 口味 |
| scene | 场景 |
| cuisine | 菜系 |
| tool | 工具 |
| custom | 自定义 |

## 4. dishes 菜品表

```sql
CREATE TABLE dishes (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(120) NOT NULL,
    cover_image_url TEXT,
    source_url TEXT,
    source_platform VARCHAR(50),
    description TEXT,
    status VARCHAR(30) NOT NULL DEFAULT 'want_to_cook',
    rating NUMERIC(2,1),
    difficulty SMALLINT,
    cook_time_minutes INTEGER,
    main_ingredients TEXT,
    taste VARCHAR(80),
    scene VARCHAR(80),
    note TEXT,
    last_cooked_at TIMESTAMPTZ,
    cook_count INTEGER NOT NULL DEFAULT 0,
    is_favorite BOOLEAN NOT NULL DEFAULT FALSE,
    extra JSONB NOT NULL DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at TIMESTAMPTZ
);

CREATE INDEX idx_dishes_status ON dishes(status) WHERE deleted_at IS NULL;
CREATE INDEX idx_dishes_last_cooked_at ON dishes(last_cooked_at) WHERE deleted_at IS NULL;
CREATE INDEX idx_dishes_rating ON dishes(rating) WHERE deleted_at IS NULL;
CREATE INDEX idx_dishes_name ON dishes(name) WHERE deleted_at IS NULL;
```

## 5. cook_records 制作记录表

```sql
CREATE TABLE cook_records (
    id BIGSERIAL PRIMARY KEY,
    dish_id BIGINT NOT NULL REFERENCES dishes(id) ON DELETE CASCADE,
    cooked_at TIMESTAMPTZ NOT NULL,
    result VARCHAR(30) NOT NULL DEFAULT 'normal',
    rating NUMERIC(2,1),
    notes TEXT,
    changes TEXT,
    failure_reason TEXT,
    next_improvement TEXT,
    extra JSONB NOT NULL DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at TIMESTAMPTZ
);

CREATE INDEX idx_cook_records_dish_id ON cook_records(dish_id) WHERE deleted_at IS NULL;
CREATE INDEX idx_cook_records_cooked_at ON cook_records(cooked_at) WHERE deleted_at IS NULL;
CREATE INDEX idx_cook_records_result ON cook_records(result) WHERE deleted_at IS NULL;
```

## 6. tags 标签表

```sql
CREATE TABLE tags (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    type VARCHAR(30) NOT NULL DEFAULT 'custom',
    usage_count INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at TIMESTAMPTZ,
    CONSTRAINT uk_tags_name_type UNIQUE(name, type)
);

CREATE INDEX idx_tags_type ON tags(type) WHERE deleted_at IS NULL;
CREATE INDEX idx_tags_usage_count ON tags(usage_count) WHERE deleted_at IS NULL;
```

## 7. dish_tags 关联表

```sql
CREATE TABLE dish_tags (
    dish_id BIGINT NOT NULL REFERENCES dishes(id) ON DELETE CASCADE,
    tag_id BIGINT NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (dish_id, tag_id)
);

CREATE INDEX idx_dish_tags_tag_id ON dish_tags(tag_id);
```

## 8. attachments 图片附件表

```sql
CREATE TABLE attachments (
    id BIGSERIAL PRIMARY KEY,
    biz_type VARCHAR(50) NOT NULL,
    biz_id BIGINT NOT NULL,
    file_name VARCHAR(255) NOT NULL,
    file_url TEXT NOT NULL,
    thumbnail_url TEXT,
    mime_type VARCHAR(80),
    file_size BIGINT,
    width INTEGER,
    height INTEGER,
    sort_order INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at TIMESTAMPTZ
);

CREATE INDEX idx_attachments_biz ON attachments(biz_type, biz_id) WHERE deleted_at IS NULL;
```

biz_type 建议：dish_cover、cook_record、source_screenshot。

## 9. recook_plans 复做计划表

```sql
CREATE TABLE recook_plans (
    id BIGSERIAL PRIMARY KEY,
    dish_id BIGINT NOT NULL REFERENCES dishes(id) ON DELETE CASCADE,
    planned_date DATE,
    status VARCHAR(30) NOT NULL DEFAULT 'active',
    reason TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    completed_at TIMESTAMPTZ,
    deleted_at TIMESTAMPTZ
);

CREATE INDEX idx_recook_plans_status ON recook_plans(status) WHERE deleted_at IS NULL;
CREATE INDEX idx_recook_plans_planned_date ON recook_plans(planned_date) WHERE deleted_at IS NULL;
```

## 10. app_settings 应用设置表

```sql
CREATE TABLE app_settings (

    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()

```

## 11. 常用查询示例

### 11.1 很久没做但评分高

```sql
SELECT * FROM dishes
WHERE deleted_at IS NULL
  AND rating >= 4.0
  AND status IN ('success', 'want_to_recook')
  AND (last_cooked_at IS NULL OR last_cooked_at < NOW() - INTERVAL '30 days')
ORDER BY last_cooked_at ASC NULLS FIRST
LIMIT 6;
```

### 11.2 关键词搜索

```sql
SELECT DISTINCT d.*
FROM dishes d
LEFT JOIN dish_tags dt ON d.id = dt.dish_id
LEFT JOIN tags t ON dt.tag_id = t.id AND t.deleted_at IS NULL
WHERE d.deleted_at IS NULL
  AND (
    d.name ILIKE '%' || $1 || '%'
    OR d.main_ingredients ILIKE '%' || $1 || '%'
    OR d.note ILIKE '%' || $1 || '%'
    OR t.name ILIKE '%' || $1 || '%'
  )
ORDER BY d.updated_at DESC;
```

## 12. 数据更新规则

新增制作记录后，应更新 dishes：cook_count、last_cooked_at、rating。rating MVP 推荐取有效制作记录评分平均值；若 result = success，可提示用户将菜品状态更新为 success。
